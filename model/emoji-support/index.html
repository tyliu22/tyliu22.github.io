Python is a popular, high-level, general-purpose programming language known for its simplicity and readability. A virtual environment is an isolated Python environment that allows you to work on a project without affecting the global Python installation or other projects. It ensures that dependencies for one project do not interfere with others. Dependencies are external libraries or packages that a Python project requires to function. 

Task: Suppose you have several ML projects, each project requires a seperate python environment with different python version. To achieve this, there are three subtasks:

  • Python version management
    • Python virtual environment management
    • Package dependency management

How to configure Python virtual environment#

Python environment software#

Use pip#

pip : default package manager for Python, used to install, upgrade, and manage Python packages and libraries from the Python Package Index (PyPI) or other repositories.

Key features:

  • Install from requirements.txt or from a Local File or URL
    • Global installation:
      • If you run pip without activating a virtual environment.
      • When no virtual environment is active, pip installs packages globally, typically in the system-wide Python installation directory.
    • Virtual environment installation:
      • If you activate a virtual environment before running pip.
      • When a virtual environment is active, pip installs packages only within the virtual environment’s directory, isolating them from the global environment.

Use venv (Build-in)#

venv: Lightweight and simple virtual environment for small to medium projects. Key features:

  • comes with pre-installed with Python (3.3+)
    • minimal external dependencies Steps:
# Create a virtual environment
python -m venv myenv

# Activate the environment
# On Windows:
myenv\Scripts\activate
# On macOS/Linux:
source myenv/bin/activate

# Deactivate
deactivate

Use virtualenv#

virtualenv : virtual environment, not build-in. Best for advanced features and compatibility with older Python versions (<3.3) Key features:

  • Allows creation of virtual environments for both Python 2 and 3.
    • Faster environment creation compared to venv. Steps:
# Install virtualenv (not build in)
pip install virtualenv

# Create a virtual environment
virtualenv myenv

# Activate the environment
source myenv/bin/activate  # macOS/Linux
myenv\Scripts\activate     # Windows

# Deactivate
deactivate

Use pipenv#

pipenv : Virtual environment and dependency management in one tool. Key features:

  • automatically creates a virtual environment.
    • uses Pipfile for dependency tracking (replaces requirements.txt). Steps:
# Install pipenv
pip install pipenv

# Create a virtual environment and install dependencies
pipenv install pendulum

# Activate the virtual environment
pipenv shell

# Deactivate
exit

Use poetry#

poetry : Managing virtual environments, dependencies, and project structure in modern Python projects. Creating a project (sets up virtual environment automatically) and initialising a pre-existing projects step by step.

Key Features:

  • Combines virtual environment creation and dependency management.
    • Uses pyproject.toml.

Steps:

# Install Poetry
pip install poetry

# Create a project (sets up virtual environment automatically)
poetry new my_project
# Or initialising a pre-existing project
cd pre-existing-project
poetry init

# Add dependencies
poetry add torch

# Activate the environment
poetry shell

# Deactivate
exit

Use pyenv#

pyenv : Manages multiple Python versions. While not a virtual environment tool itself.

Key features:

  • Easily switch between Python versions.
    • Works with pyenv-virtualenv to create isolated environments.

Steps:

# Create a new python version
pyenv install <version>

# Create a virtual environment
pyenv virtualenv <version> <env_name>

# Activate the environment
pyenv activate <env_name>

Use Conda or Anaconda#

Conda or Anaconda : Data science and machine learning projects, or when working with non-Python dependencies. Conda is an open-source lightweight package, dependency, and environment management system. Anaconda is a distribution of Conda that comes prepackaged with a large number of data science, machine learning, and scientific computing libraries and tools.

Key Features:

  • Manages Python and non-Python packages.
    • Cross-platform compatibility.

Steps:

# Create a virtual environment
conda create --name myenv python=3.10

# Activate the environment
conda activate myenv

# Deactivate
conda deactivate

Use nox#

nox : Managing testing environments for multiple Python versions.

Key features:

  • Automates environment setup and testing tasks.

Steps:

  • Step 1: noxfile.py:
import nox

@nox.session(python=["3.9", "3.10"])
def tests(session):
    session.install("pytest")
    session.run("pytest")
  • Step 2: Run environments
nox

Combination choices for Python projects#

When starting a Python project after installing Python, you have multiple ways to install and manage python versions, virtual environments and dependencies. In this part, we introduce several different ways:

  • system python + venv + pip
  • pyenv + venv + pip
  • pyenv + poetry

1. Lightweight Setup: Python + venv + pip#

User case: Simple and small script or utility projects or when you’re working with one Python version. Management:

  • Python versions: system python;
    • Virtual environments: venv;
    • Dependencies: pip Use the python version installed on your system. Create a virtual environment with venv and manage dependencies with pip.

Steps:

python -m venv myenv

python -m venv myenv

pip install <package>

2. Multiple Python Versions: pyenv + venv + pip#

User case: Simple projects when you’re working with different Python versions. Management:

  • Python versions: pyenv;
    • Virtual environments: venv;
    • Dependencies: pip Manage python versions with pyenv. Create a virtual environment with venv and manage dependencies with pip.

Steps:

pyenv install 3.8.10
pyenv install 3.10.5
pyenv local 3.8.10  # Set Python version for the current project

python -m venv myenv

pip install <package>

3. Modern Standard: pyenv + Poetry (Recommendation)#

User case: Modern, structured projects needing specific Python versions and dependency management. Management:

  • Python versions: pyenv;
    • Virtual environments: poetry;
    • Dependencies: poetry Manage python versions with pyenv. Create a virtual environment with poetry and manage dependencies with poetry.

Steps:

pyenv install 3.9.7
pyenv local 3.9.7  # Set Python version for the current project

poetry new my_project
cd my_project
poetry add flask
poetry shell  # Activates Poetry's virtual environment

4. Full Isolation: Docker#

User case: Production-like environments or team projects where the system Python version should not be used.

Steps:

  • Step 1: create a Dockerfile
FROM python:3.10
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt
CMD ["python", "app.py"]
  • Step 2: Build and run the container
docker build -t my-python-app .
docker run -it my-python-app

5. Data Science Workflow: Conda#

User case: Data science, machine learning, or projects needing non-Python dependencies.

Steps:

  • Step 1: create a Dockerfile
conda create --name myenv python=3.9
conda activate myenv

conda install numpy pandas

6. Testing Across Python Versions: pyenv + nox#

User case: Automated testing for compatibility across multiple Python versions.

Steps:

  • Step 1: create a noxfile.py
import nox

@nox.session(python=["3.8", "3.9", "3.10"])
def tests(session):
    session.install("pytest")
    session.run("pytest")
  • Step 2: Run tests in all environments
nox

Combination Choices#

Combination Python Version Management Virtual Environment Dependency Management Best For
Python + venv + pip System Python venv pip Small, simple projects
pyenv + venv + pip pyenv venv pip Projects needing different Python versions
pyenv + Poetry pyenv Poetry’s built-in env Poetry Modern, structured, multi-version projects
Docker Docker image Docker container pip Reproducible, production-like environments

pyenv + nox pyenv nox testing env pip Testing compatibility across versions

How to deploy poetry Python project on Docker#

configuring poetry for projects#

Ensure you have Poetry installed on your system via running

poetry --version

Configuring Poetry for a New Project#

Poetry can create a structured project directory with a pyproject.toml file for dependencies and project metadata.

Step 1: create a new project

poetry new my_project

This generates the following structure:

my_project/
├── pyproject.toml
├── README.rst
├── my_project
│   └── __init__.py
├── tests
    └── __init__.py

Step 2: Add Dependencies:

poetry add torch

# Add a development dependency
poetry add --dev pytest

Step 3: Activate the Virtual Environment

poetry shell

Step 4: Use poetry run to execute commands inside the environment

poetry run python main.py

Configuring Poetry for a Pre-existing Project#

For an existing project, you can initialize Poetry to manage dependencies.

Step 1: Navigate to the Project Directory

cd my_existing_project

Step 2: Initialize Poetry

poetry init

This will prompt you to provide:

  • Project name
  • Version
  • Description
  • Author details
  • License
  • Dependencies Once completed, a pyproject.toml file is created.

Step 3: Add Dependencies

# Add dependencies from `requirements.txt` directly
poetry add $(cat requirements.txt | xargs)
# Add dependencies
poetry add flask

Step 4: To install dependencies specified in pyproject.toml

poetry install

Step 5: Activate the Virtual Environment

poetry shell

Example Workflow#

Creating a New Project:

poetry new my_project
cd my_project
poetry add torch
poetry shell
python -m torch --version

Using Poetry in an Existing Project:

cd existing_project
poetry init
poetry add flask pytest
poetry install
poetry shell
pytest

Configuring Docker for Python projects#

Configuring Docker for common web/non-web Python projects#

This mainly consists of several steps: configure Dockerfile, build docker image, and then run the Docker container

Step 1: Install Docker

# verify the installation
docker --version

Step 2: Create a Python Project (option)

mkdir my-python-project
cd my-python-project
touch main.py

Add some sample code in app.py

print("Hello, Docker!")

Step 3: Create a requirements.txt List your dependencies in a requirements.txt file:

pendulum

Step 4: Create a Dockerfile The Dockerfile defines the environment and how the application is built and run.

# Use an official Python image
FROM python:3.10-slim

# Set the working directory in the container
WORKDIR /app

# Copy the project files into the container
COPY . .

# Install dependencies
RUN pip install --no-cache-dir -r requirements.txt

# Expose a port if you're running a web app. For a standard Python project (e.g., a script, data processing task, CLI tool, etc.), there’s no need for `EXPOSE`
EXPOSE 5000

# Define the command to run the application
CMD ["python", "main.py"]

Step 5: Build the Docker Image Build the image from the Dockerfile:

docker build -t my-python-app .

Step 6: Run the Docker Container Run the container using the built image:

docker run -it --rm my-python-app
  • -it: Interactive terminal.
  • --rm: Automatically remove the container after it exits.

If you’re running a web app, map the ports:

docker run -it --rm -p 5000:5000 my-python-app

Step 7: Using docker-compose (Optional) If your project has multiple services (e.g., a database), use docker-compose for easier management.

Example docker-compose.yml:

version: '3.9'

services:
  web:
    build:
      context: .
    ports:
      - "5000:5000"
    volumes:
      - .:/app
    command: python main.py

Run the services:

docker-compose up

Step 8: Configure .dockerignore Add a .dockerignore file to exclude unnecessary files from the build context:

*.pyc
__pycache__/
.env

Check container logs

docker logs <container_id>

Step 9: Example for Flask Web App

If you’re using Flask, the main.py might look like this:

from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Hello, Docker with Flask!"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

Update the Dockerfile to expose Flask’s port:

EXPOSE 5000

Summary Workflow

  1. Write your application code (main.py).
  2. Create a requirements.txt for dependencies.
  3. Write a Dockerfile to define the environment.
  4. Build the Docker image:
docker build -t my-python-app .
  1. Run the container:
docker run -it --rm -p 5000:5000 my-python-app

Advanced Configuration

  • Environment Variables: Pass variables using the -e flag or .env file.
docker run -it -e FLASK_ENV=development my-python-app
  • Bind Volumes: Sync code changes without rebuilding
docker run -it -v $(pwd):/app my-python-app
  • Multi-stage Builds: Optimize production builds.

Configuring poetry project in Docker#

Poetry replaces requirements.txt with its own modern dependency tracking system using the pyproject.toml and poetry.lock files. Here’s what you should do to manage dependencies or generate a requirements.txt if needed:

Use poetry add to add dependencies and install all dependencies listed in pyproject.toml

# Add dependencies
poetry add pendulum

# install all dependencies listed in `pyproject.toml` 
poetry install
How to configure poetry project in Docker#
  1. Generate a requirements.txt from Poetry
poetry export -f requirements.txt --output requirements.txt
  1. Using Poetry in Docker Without requirements.txt
# Use an official Python image
FROM python:3.10-slim

# Set the working directory inside the container
WORKDIR /app

# Install Poetry globally
RUN pip install poetry

# Copy Poetry configuration files to the container
COPY pyproject.toml poetry.lock ./

# Install project dependencies using Poetry
RUN poetry install --no-root

# Copy the rest of the application code
COPY . .

# Define the default command to run the application
CMD ["poetry", "run", "python", "main.py"]
  1. Adding environment variables (Optional) If your project uses environment variables, you can pass them into the container:
  • Add a .env file in your project:
DEBUG=True
SECRET_KEY=mysecretkey
  • Update the Dockerfile to install python-dotenv and load environment variables:
# Install python-dotenv
RUN poetry add python-dotenv

# Copy the .env file
COPY .env .env
  • Pass environment variables while running the container:
docker run -it --rm --env-file .env my-poetry-app
  1. Using docker-compose for Multi-Service Projects. If your project involves multiple services (e.g., a database), use docker-compose.

Example docker-compose.yml:

version: "3.9"

services:
  web:
    build:
      context: .
    ports:
      - "5000:5000"
    volumes:
      - .:/app
    command: poetry run python main.py

Run the services:

docker-compose up

docker-compose.yml with Multiple Services#

When you python project is related to multiple services, such as web app, database and cache, in this case, a docker-compose.yml is required to manage multiple Docker containers (services) and their relationships.

Comparison between Dockerfile and docker-compose.yml#

Dockerfile: A Dockerfile is a script containing instructions to build a Docker image for your application. It focuses on creating a single Docker image, and build a custom environment for your application.

Builds an Image:

  • Specifies the base image (e.g., python:3.10-slim).
  • Contains commands to install dependencies, copy application files, and define the container runtime behavior. Example:
# Dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt
CMD ["python", "app.py"]

When to use:

  • Always required if you need a custom image for your application.

docker-compose.yml: A docker-compose.yml file defines and manages multiple Docker containers (services) and their relationships. It focuses on managing and running multiple services (containers) and orchestrates multiple services, such as web apps, databases, caches, etc., in a unified setup.

Service Orchestration:

  • Defines and runs multiple containers (services) together.
  • Specifies how services interact (e.g., a web app connects to a database). Example:
# docker-compose.yml
version: "3.9"
services:
  web:
    build:
      context: .
    ports:
      - "5000:5000"
  db:
    image: postgres:13
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password

When to use:

  • When your application involves multiple services (e.g., a web server, database, and message queue).
  • Simplifies running containers by combining docker run commands into a single configuration.

Command Usage Dockerfile

# Build an Image
docker build -t my-app .

# Run a Container
docker run -it --rm my-app

codker-compose.yml

# Run all services
docker-compose up

# Stop all services
docker-compose down

Key Differences#

Feature Dockerfile docker-compose.yml
Scope Builds a single image. Manages and runs multiple containers as a group.
Complexity Simpler, focuses on building the image. More complex, includes networking and relationships between services.
Networking Does not handle networking. Automatically sets up a default network for services to communicate with each other.
Environment Variables Can be set during container runtime. Defines environment variables for multiple containers in one place.
File Format Dockerfile syntax (specific to Docker builds). YAML, used to define services, volumes, networks, and configurations.
Dependency Orchestration Not supported (handles only one container). Supports orchestration and dependency startup (e.g., wait for the database to be ready).

When using docker-compose.yml, you typically configure a Dockerfile for each service that requires a custom image. The docker-compose.yml orchestrates the services, and the Dockerfile defines how the image for each service is built.

Why Configure a Dockerfile for Each Project?

  • Custom Configuration: Each service might need a unique setup. For example:
    • A Python web app might need dependencies from pyproject.toml or requirements.txt.
    • A database service like PostgreSQL might use a standard image with additional configuration files.
  • Environment Isolation: Using a Dockerfile ensures that each service is built with the required dependencies and configurations.
  • Version Control: You can track changes in your custom images by managing the Dockerfile in your project’s repository.

When Is a Dockerfile Needed? You need a Dockerfile if:

  • The service requires specific dependencies, environment variables, or configurations.
  • The service uses custom application code (e.g., a Python application).
  • You’re not using a pre-built image or you need to extend it. You don’t need a Dockerfile if:
  • The service uses a standard image with no modifications (e.g., postgres, redis, etc.).
Full example workflow docker-compose.yml with Multiple Services#

Here’s an example with two services: a Python Flask app (with a custom Dockerfile) and a PostgreSQL database (using a pre-built image).

Directory Structure:

my_project/
├── app/
│   ├── app.py
│   ├── pyproject.toml
│   ├── poetry.lock
│   ├── Dockerfile
├── docker-compose.yml
  1. Dockerfile for the Flask App This file defines the custom image for the Python service.
# Use a lightweight Python image
FROM python:3.10-slim

# Set the working directory inside the container
WORKDIR /app

# Install Poetry
RUN pip install poetry

# Copy Poetry configuration files
COPY pyproject.toml poetry.lock ./

# Install dependencies using Poetry
RUN poetry install --no-root

# Copy the application code
COPY . .

# Expose the Flask default port
EXPOSE 5000

# Define the command to run the app
CMD ["poetry", "run", "python", "app.py"]
  1. docker-compose.yml

This file orchestrates both the Flask app and PostgreSQL database.

version: "3.9"
services:
  web:
    build:
      context: ./app
    ports:
      - "5000:5000"  # Map container port 5000 to host port 5000
    environment:
      - FLASK_ENV=development  # Flask environment variable
    depends_on:
      - db  # Ensure the database starts before the web app

  db:
    image: postgres:13  # Uses the official `postgres:13` image.    
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: mydb
    ports:
      - "5432:5432"  # Map container port 5432 to host port 5432
    volumes:
      - postgres_data:/var/lib/postgresql/data  # Persist database data

volumes:
  postgres_data:  # Named volume for database persistence

How the Configuration Works

  1. Python Service (web):
    • Uses the Dockerfile in the app/ directory to build a custom image.
    • Maps port 5000 on the container to port 5000 on the host.
    • Waits for the database (db) service to be ready before starting.
  2. PostgreSQL Service (db):
    • Uses the official postgres:13 image.
    • Configures database credentials and a persistent volume.
